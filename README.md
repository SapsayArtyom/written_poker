# Расписной покер

Стол для расписного покера: приложение ведёт расписку и считает очки, а карты
раздаются живой колодой. Интерфейс рассчитан в первую очередь на телефон:
крупные зоны нажатия, главное действие в липкой панели снизу, переключатель
«Ход / Расписка» вместо двух колонок.

## Два режима стола

**Один ведёт стол** (по умолчанию при создании). Один человек заходит с
авторизацией и становится админом: сам добавляет игроков — только имена,
аккаунты им не нужны, — выставляет порядок хода и вводит за всех заказы и
взятки со своего устройства. Остальные в приложение не заходят.

В этом режиме заказ пишется **сразу по нажатию цифры**, без подтверждения:
за партию на шестерых это экономит больше сотни нажатий, а ошибка снимается
кнопкой «Отменить заказ». Кто угодно ещё может открыть стол по ссылке и
следить за распиской, но вводить ничего не сможет.

**Каждый со своего устройства.** Игроки авторизуются сами, садятся за стол
в лобби и делают заказ со своего телефона; хост может ввести заказ за
опаздывающего. Состояние стола синхронно у всех.

Режим выбирается при создании стола и дальше не меняется — он определяет,
кто вправе что вводить.

## Стол и партии

Стол живёт дольше партии: состав игроков в нём сохраняется, а партий за столом
можно сыграть сколько угодно.

- **Новая партия** — с экрана стола, кнопкой «Начать партию N». Перед стартом
  можно поменять очерёдность игроков стрелками.
- **Конец партии** — итоги, затем «К столу — новая партия»: сводка уходит
  в архив стола и показывается в списке «Сыгранные партии».
- **Сбросить партию** — выбросить недоигранную партию, не записывая в архив.
  Спрашивает подтверждение.
- **Переименовать или удалить стол** — там же, у админа. Удаление спрашивает
  подтверждение и невозможно во время партии.

В архив пишется сводка партии (номер, число раундов, места и очки), а не вся
расписка: иначе документ стола после десятка партий упёрся бы в лимит Firestore
на один документ.

## Стек

- React + Vite + **TypeScript** (strict)
- Zustand — состояние клиента
- Firebase Authentication (Google + анонимный гость)
- Cloud Firestore — состояние комнат в реальном времени
- Vitest + Testing Library — правила, движок и сквозной прогон интерфейса

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # 127 тестов
npm run typecheck  # tsc --noEmit
npm run build
```

`.env` уже заполнен конфигом проекта `written-poker`. Если ключи убрать,
приложение поднимет **локальный режим** на `localStorage` — столы и расписка
живут в браузере, вход только по имени, а несколько окон синхронизируются
через событие `storage`. Это удобно для разработки без сети.

Тесты всегда идут в локальном режиме: ключи гасятся в `test.env`
([vite.config.ts](vite.config.ts)), чтобы прогон не стучался в реальный Firestore.

### Состояние проекта Firebase

Проект `written-poker` проверен запросами и готов к игре:

- **Anonymous-вход** включён — вход по имени работает.
- **Правила Firestore** опубликованы: под авторизованным токеном чтение и запись
  комнат проходят, без токена — `PERMISSION_DENIED`. Удалять комнату может
  только её хост.
- Форма документа комнаты (массив игроков, история раундов с картами очков)
  Firestore принимается без нареканий.

Осталось на будущее:

- **Google** как способ входа — включить, если он нужен помимо гостевого.
- Для GitHub Pages добавить домен `<user>.github.io` в
  **Authentication → Settings → Authorized domains** (пока разрешены
  `localhost`, `written-poker.firebaseapp.com`, `written-poker.web.app`).

Ошибки настройки приложение показывает человеческим текстом с подсказкой, что
именно включить ([src/services/errors.ts](src/services/errors.ts)).

Правила сейчас разрешают любому авторизованному игроку писать в любую комнату —
этого достаточно для своей компании. Перед публичным запуском стоит ужесточить:
проверять, что пишущий состоит в `players`, а `game`/`history` меняет только хост.

### Локальные эмуляторы вместо облака

```bash
npm i -g firebase-tools
cd firebase && firebase emulators:start --only auth,firestore
```

В `.env` поставить `VITE_USE_EMULATORS=true`. Эмулятору Firestore нужна Java.

## Правила, которые реализованы

### Состав и сетка раундов

Играют 2, 4 или 6 игроков — только чётное число, чтобы колода из 36 карт
раздавалась без остатка. Максимум карт на игрока = `36 / число игроков`.

Сетка строится автоматически ([src/game/rounds.ts](src/game/rounds.ts)):

1. **Подъём** — по 1, 2, 3 … до максимума карт.
2. **Плато** — раздача по максимуму повторяется столько раз, сколько игроков
   (каждый по разу сдаёт максимум).
3. **Спуск** — обратно до 1 карты.
4. **Спецсерии** — Б (безкозырка), Т (тёмные), М (мизера), З (золотые);
   каждая длится «число игроков» раундов и всегда идёт по максимуму карт.

| Игроков | Максимум карт | Основных раундов | Спецраундов | Всего |
| ------- | ------------- | ---------------- | ----------- | ----- |
| 2       | 18            | 36               | 8           | 44    |
| 4       | 9             | 20               | 16          | 36    |
| 6       | 6             | 16               | 24          | 40    |

Раунд 1 начинает первый игрок, каждый следующий раунд — следующий по кругу.

### Раздача и порядок заказа

Первый раунд раздаёт тот, кто стоит первым в списке игроков; дальше сдача идёт
по кругу. **Заказывать начинает следующий за раздающим**, поэтому раздающий
заказывает последним — и именно ему достаётся запрет на «добивающее» число.

Кто раздаёт и кто заказывает первым, написано в шапке раунда. В расписке
у каждого раунда рядом с номером стоит первая буква имени раздающего.

Заказывают строго по очереди — порядок нарушить нельзя даже админу. Сумма
заказов не может быть равна числу розданных карт, поэтому последнему
заказывающему запрещённое значение блокируется в интерфейсе с пояснением,
почему.

### Очки

| Ситуация                            | Очки                     |
| ----------------------------------- | ------------------------ |
| Заказал N, взял ровно N             | N × 10                   |
| Пас (заказ 0), не взял ни одной     | 5                        |
| Недобор                             | −10 за каждую невзятую   |
| Перебор (заказ не оплачивается)     | +1 за каждую взятку      |
| Пас не сдержан (заказал 0, но взял) | +1 за каждую взятку      |
| Б (безкозырка) и Т (тёмные)         | всё выше × 2             |
| З (золотые)                         | всё выше × 5             |

Лишние взятки (перебор и взятки при пасе) множителем раунда не умножаются —
это регулируется флагом `multiplyExtras`.

### Мизера (М)

Особый раунд: **заказа нет**, все стараются не взять ни одной взятки. Раунд
сразу открывается на вводе взяток, минуя фазу заказа.

- не взял ни одной → **+10** (пас с множителем ×2)
- каждая взятая взятка → **−20**

Числа берутся из `passValue` и `misereTrickPenalty`; если у вас за столом
считают иначе, всё правится в `DEFAULT_RULES`
([src/game/scoring.ts](src/game/scoring.ts)) — весь подсчёт идёт через одну
функцию `scorePlayerRound`.

## Структура

```
src/
  types.ts       общие типы: Room, GameState, Round, Rules, HistoryEntry
  game/          чистые правила, без React и Firebase
    rounds.ts      сетка раундов и порядок хода
    scoring.ts     подсчёт очков
    validation.ts  запрет на заказ, проверка суммы взяток
    engine.ts      переходы состояния партии и архив (покрыт тестами целиком)
    table.ts       состав стола, имя стола, операции админа
    view.ts        производное состояние для рендера
  services/      бэкенды: firebase (auth/rooms/game) и localBackend
    backend.ts     выбирает бэкенд по наличию ключей в .env
    errors.ts      человеческие тексты ошибок Firebase
  store/         Zustand: auth, лобби, текущая комната
  components/    UI-блоки: состав стола, заказы, взятки, расписка, итоги
  pages/         вход, лобби, стол
  styles/        mobile-first CSS
firebase/        правила Firestore и конфиг эмуляторов
```

Логика хода живёт в `src/game/engine.ts` и возвращает набор полей для записи;
бэкенды только оборачивают её — Firestore в `runTransaction`, локальный
в `localStorage`. Поэтому оба режима считают одинаково, а партия целиком
проигрывается в тестах.

## Мобильный интерфейс

- Раскладка mobile-first, единственный медиазапрос — `min-width: 900px`,
  где стол превращается в две колонки, а переключатель разделов исчезает.
- Главное действие всегда в липкой панели снизу с учётом `safe-area-inset`;
  страница резервирует под неё место, чтобы панель не накрывала контент.
- Кнопки заказа — сетка `auto-fit` от 56 px, счётчики взяток по 40 px,
  минимальная высота интерактивных элементов 48 px.
- Расписка прокручивается по горизонтали, столбец с номером раунда липкий.
- Поля ввода 16 px, чтобы iOS не зумил страницу при фокусе.
- Приглашение за стол уходит через `navigator.share`, с откатом в буфер обмена.
- Опасные действия — возврат к прошлому раунду, отмена заказа, сброс партии,
  удаление стола — спрашивают подтверждение: на телефоне такие кнопки слишком
  легко задеть. Диалог выезжает снизу, под палец.
- В расписке колонки игроков одной ширины, длинные имена обрезаются, а строка
  «Итого» скрыта под кнопкой «Показать итог».

## Модель данных

Один документ на комнату — `rooms/{roomId}`:

```ts
{
  name, mode, hostId, status,    // mode: online | single; status: waiting | playing | finished
  players: [{ uid, name, photoURL, isGuest, isLocal }], // порядок массива = порядок хода
  rules: Rules,
  game: {
    playerOrder: Uid[],
    roundIndex, phase,           // bidding | results | finished
    bids: Record<Uid, number>,   // в мизерах пустой
  },
  history: [{ roundIndex, cards, kind, bids, tricks, scores }],  // текущая партия
  games: [{ number, rounds, startedAt, finishedAt, playerOrder, results }], // архив
}
```

Все ходы идут через транзакцию, поэтому два одновременных заказа не разъезжаются.

В режиме `single` игроки — это записи с `isLocal: true` и местами `p1…p6`;
своих аккаунтов у них нет, а `hostId` указывает на аккаунт админа, которого
в `players` может и не быть, если он только считает. Документ без поля `mode`
(созданный до появления режимов) читается как `online`.
